## 十二步验收

1. 原库为空，创建三张表成功，无警告，初始行数全为 0。
2. 导入预览校验不写入学生数据。
3. 导入两名专门标记的虚拟学生，带前导零的学号、负积分、搜索与分页读写正确。
4. 概率合计为 1，负积分可参与随机点名；保存的种子与快照能够复演同一结果。
5. 到场、准确复述、回答 3 分结算为 +4.5；重复请求返回 409；单条记录查询能恢复已保存分项。
6. 顺序点名不增加随机次数；未到场的零增量能够正常结算。
7. 同一记录并发结算，结果为一个成功、一个 409，学生只增加一次积分。
8. 同一学生两条记录并发结算，两次增量都保留。
9. 在真实事务中注入积分流水写入失败，记录状态、学生积分和流水完整回滚；正常重试成功。
10. 在真实事务中注入导入完成后的故障，新增学生回滚；正常重复学号导入只更新姓名专业，保留积分和随机次数。
11. 关闭并重建 HTTP 服务及连接池，名单、积分、次数与结算记录仍从数据库正确读回；排行、全量导出正常。
12. 按此次生成的明确学号列表，事务内删除其积分流水、点名记录及学生；复查三表恢复为 0 行。没有 DROP、TRUNCATE、重置序列或清理非测试记录。

## 当前使用方式

```powershell
npm ci
# .env 已配置者不需要重复复制或覆盖。
npm run start:mysql
```

浏览器访问 http://127.0.0.1:8787/ 。本轮已实际启动 MySQL 入口并验证根页面 200、学生接口返回 0 人。页面名单为空是因为数据库刚建立且验收数据已经清理；导入实际名单后会持久保存。

`node server/index.js` 默认仍为内存演示模式，不自动读取 .env。日常使用真实数据库时必须执行 `npm run start:mysql`，避免把演示数据误认为数据库数据。
