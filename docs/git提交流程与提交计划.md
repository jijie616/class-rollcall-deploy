## 二、commit 时间间隔会不会导致扣分

### 先看题目原文怎么写

翻遍 `任务3.docx`，与 commit 相关的只有两处：

- 评分细则「3.7 贴出代码commit记录」（2 分）——**只要求"贴出"，没有给出任何关于提交频率、间隔、时间分布的评分标准**；
- 提交注意事项第 6 条「抄袭或作弊：自动评测系统或人工检测到的不诚信行为评为0分（包括但不限于作业抄袭、抽取非随机等）」——**列举的是抄袭与抽取非随机，不涉及提交时间**。

**结论：题目没有把"提交间隔短"列为扣分项。** 这是从原文得出的，不是推测。

### 但确实存在一类真实风险，它不是"频率"，而是"证据一致性"

commit 记录唯一会被质疑的地方，是它与博客其他部分对不上。三个具体检查点：

1. **作者是否是两个不同的人。** 博客 1.1 的分工表写了杨泓负责原型、UI、图表、导出。如果 git log 里所有提交的作者都是李文龙，这份分工就没有任何证据支撑。**这一条是硬要求，也是唯一真正会出事的地方。**
2. **提交内容是否与分工对得上。** 杨泓的提交应当集中在 `src/js/ui.js`、`chart.js`、`exporter.js`、`css/style.css`；李文龙的应当集中在 `server/`、`sql/`、`src/js/lottery` 一类。如果两个人的提交都碰到所有文件，"具体分工"的说法就站不住。
3. **时间线是否与 PSP、心得体会对得上。** 如果 PSP 表填"具体编码 15 小时"，心得体会写"反复调试了三天"，而提交全部集中在某一天的几分钟内，人一眼就能看出矛盾。**这一条不需要你去调整提交时间，需要的是心得体会照实写。**

### 明确不建议做的事

**不要伪造提交时间戳。** 用 `GIT_AUTHOR_DATE` 之类手段把提交分散到不同日期，属于制造不实记录，正落在题目第 6 条说的"不诚信行为"范围内——为了规避一个本来就不存在的扣分项，去冒一个明确判 0 的风险，不划算。

### 建议做法

1. **按模块提交，不要 `git add .` 一次推完。** 本仓库的首次提交已由 `tools/init-commits.sh` 拆成 22 个逻辑提交（脚本里有完整清单），每一个都对应一个真实完成的工作单元。这样 3.7 贴出来的记录是有信息量的。
2. **杨泓的代码必须由杨泓用他自己的账号提交。** 他的模块还没开始写；等他写完 `ui.js` / `chart.js` / `exporter.js` 再提交，届时作者自然就是两个人。仓库级身份设置只影响本机本仓库，不会覆盖全局配置。
3. **从现在到 11/08 还有 3.5 周的真实开发**（UI、图表、导出、联调、部署、修缺陷），这些提交会自然分布在时间线上，不需要人为干预。
4. **心得体会照实写。** 写了几天就写几天，与提交记录互相印证而不是互相拆台。

## 三、首次提交流程

```bash
# 1. 设置本仓库作者身份（只影响本仓库，不动全局配置）
bash tools/init-commits.sh "李文龙" "你的Educoder邮箱"

# 2. 关联远程仓库（URL 以头歌页面上显示的实际地址为准）
git remote add origin <你的仓库地址>
git branch -M main

# 3. 首次推送
git push -u origin main
```

之后每完成一个模块：

```bash
git add <本模块相关文件>
git commit -m "feat(模块): 做了什么"
git push
```

提交信息规范（`type` 取值、`scope` 取值）见 `docs/分工报告.md` 第 3.6 节。
