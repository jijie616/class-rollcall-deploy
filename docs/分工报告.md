#### 3.2.2 两条必须知道的约束

**约束一：freesqldatabase / freemysqlhosting 是 MySQL 5.5，不支持 `DATETIME DEFAULT CURRENT_TIMESTAMP`。**
MySQL 5.6.5 之前，`CURRENT_TIMESTAMP` 只能作为 `TIMESTAMP` 列的默认值，用在 `DATETIME` 上会直接报 `Error 1067: Invalid default value`。因此下方建表 SQL 统一使用 `TIMESTAMP`——这样在 5.5 和 8.0 上都能跑。

**约束二：这些服务只提供数据库，不提供 web 空间。**
db4free.net 官方明确写明"provides only a MySQL database, but no web space"。浏览器 JS 无法直连 MySQL，因此必须有一个中间层（`server/`）承载数据库访问。中间层预案：

1. 首选：和前端一起部署到托管环境，由中间层出网连 3306。本机已实测出网 3306 可用，**但托管环境能否出网 3306 尚未验证**，A7 完成时须实测确认；
2. 备选：若 freesqldatabase.com 的免费档**确实包含** PHP 空间（其官网只列出免费 MySQL 套餐，PHP 主机是否含在免费档需注册后确认），则 PHP 中间层与数据库同机部署，延迟最低；
3. 兜底：中间层不可用时，前端降级为 localStorage 本地存储，保证演示不中断，但需求① 的字面符合度会下降。

> 注册页面（80/443）在本机被网络重置，无法在本机完成注册。这不代表站点不可用——独立通道实测站点均在线，且 3306 正常。**注册需在浏览器中自行完成，三家均需邮箱验证后才能开通。**

```sql
  sno           VARCHAR(20)   NOT NULL UNIQUE COMMENT '学号（必须存字符串）',
  name          VARCHAR(50)   NOT NULL        COMMENT '姓名',
  major         VARCHAR(50)                   COMMENT '专业',
  on_call_count INT           DEFAULT 0       COMMENT '随机点名次数',
  score         DECIMAL(6,2)  DEFAULT 0       COMMENT '总积分'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 点名记录表（v2：并入结算字段，加名单快照支撑"按种子复演"）
CREATE TABLE roll_records (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  sno             VARCHAR(20)  NOT NULL,
  mode            ENUM('random','sequence') NOT NULL,
  rnd_seed        BIGINT       NULL    COMMENT '随机种子（仅 random 模式），复演校验用',
  min_score       DECIMAL(6,2) NULL    COMMENT '抽签时刻的名单最低分',
  roster_snapshot TEXT         NULL    COMMENT '抽签时刻名单快照 JSON [{sno,score}]，复演校验用',
  present         TINYINT      NULL    COMMENT 'NULL=未登记；1=到场；0=未到场',
  repeat_result   ENUM('accurate','inaccurate','none') NULL COMMENT '复述结果；none=未提问',
  answer_bonus    DECIMAL(6,2) NULL   COMMENT '回答加分 0~3，0.5 步长',
  delta           DECIMAL(6,2) NULL    COMMENT '本次积分总增量',
  settled         TINYINT      NOT NULL DEFAULT 0 COMMENT '0=未结算 1=已结算；防重复加分',
  settled_at      TIMESTAMP    NULL,
  called_at       TIMESTAMP    NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_sno (sno),
  INDEX idx_time (called_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 积分流水表（v2：加 roll_id 关联结算来源）
CREATE TABLE score_logs (
  id         BIGINT AUTO_INCREMENT PRIMARY KEY,
  sno        VARCHAR(20)   NOT NULL,
  roll_id    BIGINT        NULL COMMENT '关联 roll_records.id',
  delta      DECIMAL(6,2)  NOT NULL,
  reason     VARCHAR(100)  COMMENT '加分/扣分原因',
  created_at TIMESTAMP     NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_sno (sno),
  INDEX idx_roll (roll_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**取舍说明**：
- 用 `TIMESTAMP NULL DEFAULT CURRENT_TIMESTAMP` 而非 `NOT NULL`，是为了**同时显式声明"可空"与"默认取当前时间"**，规避 MySQL 旧版本对 `TIMESTAMP` 列的隐式属性改写（旧版本会为表中第一个 `TIMESTAMP` 列自动附加更新行为，导致记录被后续 UPDATE 意外改写时间戳）。
- 每张表仍只有**一列**用 `DEFAULT CURRENT_TIMESTAMP`（roll_records 的 `called_at`、score_logs 的 `created_at`），其余时间戳列为 `TIMESTAMP NULL` 无默认值——继续满足 5.5 中"每表只能有一个 `TIMESTAMP` 列带 `CURRENT_TIMESTAMP` 默认值"的限制。
- **结算并入 roll_records（v2）**：`present / repeat_result / answer_bonus / delta / settled / settled_at` 全部落在点名记录上。一次点名对应一次结算，`settled` 标志天然实现"重复请求不能重复加分"（重复结算返回 409 ALREADY_SETTLED），不需要单独建结算表。
- **roster_snapshot 存名单快照（v2）**：复演校验需要"当时的名单"，而名单会随导入/积分变化。快照为 `TEXT` 存 JSON（60 人约 1.5KB/条），**不用 `JSON` 类型**——`JSON` 类型要 MySQL 5.7.8+，freesqldatabase 是 5.5 会直接建表失败。
- **score_logs.roll_id（v2）**：每笔积分变动可追溯到具体哪次点名，配合 `reason` 形成完整审计链。
- 不建物理外键（`FOREIGN KEY`）。免费主机上外键检查开销明显，且题目未要求；完整性由应用层保证。此点需在博客 3.2 类图中说明为有意设计。
- `sno` 全程按字符串处理。Excel 里的学号是数字，SheetJS 会解析成 number，直接入库会丢前导零且可能踩浮点精度——`importer.js` 必须强制 `String(cell).trim()`（见 3.3）。**注意：若 Excel 源文件本身就把学号存成了数字，前导零在读取前就已丢失，`String()` 无法找回**——导入器检测到疑似数字型学号时必须给出明确警告，提示把源文件学号列改为文本格式后重导。

> **⚠️ 待验证（按第零节铁律标注）**：上述 SQL 尚未在真实主机上执行过。**建表时必须先实跑一次 `schema.sql`**，确认目标主机无语法错误、无隐式属性告警；若目标是 MySQL 5.5，还要额外确认 `TIMESTAMP NULL` 的实际行为符合预期。实跑通过后本条才可改为"已验证"。

### 3.3 统一数据类型

```js
// 全项目通用，任何模块不得自行扩展字段
const Student = {
  sno: '',          // string  学号（永远字符串，禁止存 number）
  name: '',         // string  姓名
  major: '',        // string  专业
  onCallCount: 0,   // number  随机点名次数
  score: 0          // number  总积分
};
```

**类型铁律**：
- `sno` 从 Excel 读进来时**必须** `String(cell).trim()`。Excel 学号是数字，SheetJS 会解析成 number，直接落库会丢前导零、并在超过 15 位时踩浮点精度。
- `score` 涉及 0.5 步长，比较时**禁止用 `===` 直接比浮点数**，统一用 `Math.abs(a - b) < 1e-9`。
- 数据库返回的行会多一个 `id` 字段，模块内部**不得**依赖它做业务判断，业务主键统一用 `sno`。

### 3.4 分层接口契约 v2.1（当前实现基线）

#### 3.4.1 分层总览

**v2.0 架构决定：抽签与结算逻辑运行在服务端（`server/`），不在浏览器里。** 理由：① 杨泓的接口需求明确"不能由 UI 指定中签人"——算法在服务端，前端只展示，从结构上杜绝作弊嫌疑；② 结算的"防重复加分"必须有服务端唯一裁决；③ 种子、概率快照、名单快照同源落库，复演校验才成立。代价是部署多一个 Node 进程，但 `server/` 本来就是必需的中间层（免费 MySQL 无 HTTP 接口）。

```
用户操作
   ↓
ui.js（B4 杨泓）        渲染入口 renderXxx ＋ 事件回调 onXxx（3.4.2）
   ↓
app.js（A8 李文龙）     主控状态机，唯一编排者
   ↓
api.js / importer.js / exporter.js（前端：HTTP 客户端、Excel 解析、导出）
   ↓ HTTP JSON（3.4.4 / 3.4.5）
server/ 中间层（A7 李文龙）：api.js 路由 → lottery.js（A4/A5）→ scorer.js（A6）→ db.js → MySQL
```

#### 3.4.2 UI ↔ 主控契约（采纳杨泓提案，命名不变）

```js
// ui.js —— B4 杨泓。渲染入口由 app.js 调用；事件回调由 app.js 启动时注入。
UI.init(handlers)                 // 启动时注入回调，然后 app.js 调 renderStudents 首屏
UI.renderStudents(rows, total)    // 名单表：含搜索结果与空态提示
UI.renderRollResult(r)            // r = { student, mode, recordId }：点名结果（姓名/学号/专业大字展示）
UI.renderSettlement(s)            // s = { deltas, delta, score, settled }：结算面板
UI.renderRanking(rows)            // 排行榜：内部调用 Chart，负积分柱向下画
UI.renderImportPreview(preview)    // 新增：null 清除预览；否则显示 {fileName,total,conflicts,warnings}
UI.renderError(code, message)     // 统一错误提示（3.4.5 的错误码原样透传）
UI.setBusy(busy)                  // 抽签/保存/导入进行中禁用重复提交；失败后允许重试

// handlers（app.js 注入，八个事件名，保留原有六个并新增确认/取消）：
{
  onImportRequested(file),         // 仅解析文件并调 validateImport，未确认前不写库
  onImportConfirmed(),             // 提交主控保存的待导入 rows；UI 不传入另一份数据
  onImportCancelled(),             // 清除待导入名单，不写库
  onModeChanged(mode),             // 'random' | 'sequence'
  onRollRequested(),              // 点击"开始点名"
  onScoreSubmitted(payload),       // payload = { present, repeat, answerBonus }（见 3.4.6）
  onRankingRequested(limit),
  onExportRequested()
}
```

> **导入流程**：选文件 → 本地解析 → 服务端干跑校验 → 展示冲突及数字学号警告 → 确认或取消。确认调用 `api.commitImport`；库内重复仅更新姓名专业，保留积分、次数和历史。提交失败保留预览以便重试；成功后立即清除待导入状态。忙碌期间忽略重复操作。

> **存储事务**：两套 store 都提供 `withTransaction(work)`，work 使用事务专用 store。随机记录与次数、结算状态与积分及流水、整批导入分别在同一事务内提交；失败则回滚。MySQL 在同一连接上执行并锁定相关行。隔离驱动回归已通过，真实 MySQL 验收仍待完成。

> **约束**：渲染入口只负责展示，**不得**直接调用 api.js；事件回调只负责上报，**不得**自行决定业务结果。"已保存"必须来自服务端成功响应，不能仅凭按钮动画。

#### 3.4.3 业务模块契约（李文龙，服务端运行）

```js
// lottery.js —— A4 / A5（位于 server/）
Lottery.calcWeight(score, minScore)    -> number   // w = 1 / (1 + score - minScore)；分母恒 ≥ 1
Lottery.randomPick(students, rng)       -> { picked, weights, probabilities, minScore, seed }
Lottery.sequencePick(students, cursor) -> { next, roundEnded }
// cursor = 上一位的 sno；null 表示从学号最小者开始；roundEnded=true 表示本轮完成

// scorer.js —— A6（位于 server/；roll_records.settled 标志防重复结算，重复请求返回 409）
Scorer.settle(roll, { present, repeat, answerBonus })
  -> { deltas: { present, repeat, answer }, delta, score }
// repeat ∈ 'accurate'(+0.5) | 'inaccurate'(-1) | 'none'(未提问,0)
// present = 0（未到场）时 delta 恒为 0，并忽略 repeat / answerBonus —— 防止缺席被倒扣

// importer.js —— A3（前端，SheetJS 本地解析，不做网络请求）
Importer.parseFile(file, XLSX) -> Promise<{ rows, errors, warnings, header }>
// XLSX 由调用方注入（来自 lib/ 本地副本），便于在 Node 里用纯数组跑单测
// rows:      [{ row, sno, name, major }] 校验通过的行（row 为 Excel 物理行号）
// errors:    [{ row, sno, reason }] 必须修正后才能导入
// warnings:  [{ row, sno, reason }] 可继续，但需提示老师（如数字型学号的前导零风险）
// 文件内重复学号 → 计入 errors，不自动选行覆盖
Importer.commit(rows, dupPolicy, apiBase) -> Promise<{ imported, updated, rejected }>

// api.js —— A7（前端 HTTP 客户端，统一附加 API_BASE、解析 3.4.5 返回格式、抛统一错误）

// exporter.js —— B3 杨泓
Exporter.exportDetail(students)        -> void     // 直接触发 xlsx 下载

// chart.js —— B2 杨泓
Chart.renderRanking(canvasEl, ranking) -> ChartInstance

// fx.js —— B5 杨泓（本轮暂不承诺；若实现随机事件，事件判定与加分必须由服务端裁决）
```

**权重公式修正（v2 → v3 的关键变化）**：v1.0 的 `w = 1/(1+score)` 在 score = -1 时**除零**，更低分时权重为**负**——这是杨泓在原型阶段发现并提出的缺陷。v2.0 改为：

```
w = 1 / (1 + score - minScore)     （minScore = 本次抽签快照中的最低积分）
```

性质：分母 ≥ 1 恒成立、权重恒正、同一份名单内积分越高权重严格越低、全员同分时概率均等。**已用原型 8 人示例独立复算验证**：权重和 3.0146，8 个概率与原型页面显示全部吻合（陈一宁 4.15%≈4.1%……顾思齐 33.17%≈33.2%），合计 100.0%。minScore 必须取自与 `roster_snapshot` 相同的那份快照，两者一并落库，否则复演校验无法成立。

#### 3.4.5 统一返回与错误格式

```json
成功：{ "ok": true,  "data": { ... } }
失败：{ "ok": false, "error": { "code": "DUPLICATE_SNO_IN_FILE", "message": "第 7 行学号 102401306 重复" } }
```

| 错误码 | HTTP | 含义 |
| :-- | :--: | :-- |
| `VALIDATION_ERROR` | 400 | 字段缺失、学号格式非法、answerBonus 不在 0~3 的 0.5 档位 |
| `DUPLICATE_SNO_IN_FILE` | 400 | 同一文件内重复学号（附行号） |
| `EMPTY_ROSTER` | 400 | 名单为空，无法点名 |
| `NOT_FOUND` | 404 | 记录 / 学生不存在 |
| `ALREADY_SETTLED` | 409 | 该次点名已结算，拒绝重复加分 |
| `DB_UNAVAILABLE` | 503 | 数据库连接失败（前端提示重试，不静默吞掉） |
| `INTERNAL` | 500 | 未分类异常（日志留痕，不向前端暴露堆栈） |

### 5.6 为什么用 Penpot（博客 2.1 直接用这段）

原型工具经过三轮筛选，结论是 **Penpot**。把三个候选的排除理由列清楚，博客 2.1（2 分）直接改写成段落即可。

#### ① 为什么不用 Figma

| 问题 | 证据 |
| :-- | :-- |
| **免费版做不出"仅原型"链接** | Figma 官方帮助中心原文："sharing a prototype-only link is available on **paid plans**"。而 2.3「原型作品链接」要的正是原型链接（5 分） |
| **国内访问不稳** | 实测 `figma.com` **10s 超时**、`www.figma.com` 2.78s |
| **教育版对中国适用性存疑** | 官方帮助中心**英文版**仅写 "only available in select regions"，**日文版**则明列不适用中国（同列古巴/伊朗/朝鲜/俄罗斯/叙利亚）。两版口径不一，不能作为依赖 |

#### ② 为什么不用墨刀（搭档提出"墨刀收费"，核实**属实**）

墨刀官方权益页列出的免费版硬限制：

| 项目 | 免费版 | 是否卡我们 |
| :-- | :-- | :-- |
| 文件数量 | **3 个** | 不卡（我们只需 1 个文件放 5 个页面） |
| 单个原型页面数 | **20 页** | 不卡（5 个页面够） |
| 自定义分享链接数 | **1 个** | 勉强够 |
| 团队人数 | **1 人** | 不卡（原型由杨泓一人独立完成） |
| **导出原型 HTML / PDF** | **限免，带水印** | **卡**——博客 2.4 要放 6 分的原型界面图，水印很难看 |
| 单张图片容量 | 2MB | 一般够 |

**结论：墨刀的免费版对我们是"勉强能用但有水印短板"**。搭档的判断方向正确。

#### ③ 为什么用 Penpot（三条全中）

| 优势 | 证据 |
| :-- | :-- |
| **分享链接免登录** | Penpot 官方文档原文："A **Share prototype link** is a public url that you can share so that someone can see the prototype **regardless of whether they have a Penpot account**"——评委点开就能看，不用注册。这一条是决定性的 |
| **免费版核心功能不阉割** | 官方定位为开源项目，**核心设计与原型功能无付费墙**：所有交互类型、所有设计能力、所有分享功能对任何账号免费。免费档含 8 名团队成员、**无限查看者**、10GB 存储、无限设计文件 |
| **交互能力满足"交互性强"要求** | 支持 on-click / hover / double-click / right-click 触发，目标包括页面跳转、弹层开关、滚动到元素——足够拿 2.3 的 5 分 |

**国内实测（2026-10-14，各 5 次）**：`design.penpot.app` **4/5 成功、平均 1.06s**；`community.penpot.app` 5/5、1.10s。比 Figma 好得多，但**有零星超时**，比国产工具（0.23s）慢约 5 倍。

> **⚠️ 交付前必做**：Penpot 有约 20% 的超时率，**原型链接做好后，必须让搭档用手机流量（非校园网）实测打开一次**。若打不开，立即切备用方案：`js.design`（即时设计，0.23s）或 `mastergo.com`（0.27s），两者都是国产、免费档够用、支持分享链接。

**合规性说明**：题目原文列举了墨刀、Mockplus、Adobe XD、Axure RP、Figma 等工具，用的是"等"字，属举例而非穷举。Penpot 是免费开源工具，符合"采用……等免费工具实现"的要求。**博客 2.1 里要写明这一点**，避免评委以为用了没列举的付费工具。

### 5.7 关于第三方库：不用 CDN，改用本地副本

实测 2026-10-14：`cdn.jsdelivr.net` 在本机被连接重置；`cdnjs.cloudflare.com` 与 `unpkg.com` 可达。

**结论：把 Chart.js 和 SheetJS 下载到仓库 `lib/` 目录，用本地路径引入，不走 CDN。** 理由：① CDN 域名时有被墙/被重置的风险，演示当天加载不出图表是致命的；② 评委在无网或弱网环境打开也能正常显示；③ 也避免了"CDN 版本漂移导致行为变化"。同时**必须把第三方库的原作者与许可证信息写在 README 里**，这是学术诚信的一部分。
