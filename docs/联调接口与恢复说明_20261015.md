## UI 与主控

原八个回调继续保留：onImportRequested、onImportConfirmed、onImportCancelled、onModeChanged、onRollRequested、onScoreSubmitted、onRankingRequested、onExportRequested。

新增四个回调，共十二个：

| 回调                                     | 行为                                                 |
| ---------------------------------------- | ---------------------------------------------------- |
| onStudentsRequested({q,pageNo,pageSize}) | 搜索、分页、刷新或重试；每页可选 10 / 20 / 50        |
| onProbabilitiesRequested()               | 从服务端读取当前概率，再打开明细弹窗                 |
| onReplayRequested(recordId)              | 调 api.replayRoll({id:recordId})；仅随机记录提供入口 |
| onRecoveryRequested()                    | 只读核验本页保存的记录，恢复待结算或已结算状态       |

原 renderStudents(rows,total) 扩展为 renderStudents(rows,total,meta)，meta={q,pageNo,pageSize,rosterTotal}。total 为匹配人数，rosterTotal 为全班人数；主控 state.total 保持表示全班人数，state.matchedTotal 表示匹配数，state.students 仅为当前页。搜索零结果不能阻止全班点名。越过末页自动回到实际末页。

新增 renderProbabilities({minScore,total,rows})、renderReplay(result)、renderRecovery({pending,mode}) 与 clearRoll()。probabilities.total 是总权重，不能作为人数；rows.length 是参与人数。概率每次打开重新请求，不缓存旧表冒充当前概率。

renderRollResult 可接收 restored:true。恢复历史展示不计作本页新点名；会话统计依然不是全库统计。

UI 只上报操作和展示，不直接请求业务接口或决定中签人。导出始终通过 exportDetail 获取全量最新名单，不取当前页或 Top N。

## 新增 HTTP 接口

原十一个接口保留，新增第十二个：

`GET /api/roll/:id`

响应仍为 `{ok:true,data}`，data：

```js
{
  recordId, calledAt, mode,
  student: { sno, name, major, score, onCallCount },
  settled: true, // 未结算时 false
  settlement: { recordId, sno, deltas: {present,repeat,answer}, delta, score }
  // 未结算时 settlement:null
}
```

查询在同一存储事务中读取记录和学生；MySQL 使用同一连接锁定对应行。它不执行积分更新，不新建记录或流水。settlement.delta 来自原记录，分项按记录保存的评分字段恢复；score 为查询时该学生的当前总积分，可能包含之后的其他记录，不冒充原结算时的历史总分。

记录不存在返回 NOT_FOUND；非法 ID 返回 VALIDATION_ERROR。原结算重复提交仍返回 ALREADY_SETTLED，不将其无条件伪装为成功。

随机和顺序点名响应新增 calledAt，供恢复身份核对；不删除原字段。

## 结算响应丢失

1. 保存成功则按返回结果展示。
2. 遇到 NETWORK_ERROR，或本页尚无成功结果却收到 ALREADY_SETTLED，查询该记录。
3. 查询确认 settled=true，恢复原分项和当前积分，再允许继续点名；不重复提交积分。
4. 查询确认仍未结算，保留该记录及评分入口，允许用户重试；不提示已保存。
5. 查询也失败，保留“核验点名状态”入口，并锁定新点名和评分，直到核验成功。

主控也防止未结算时再次点名或切换模式；防漏记不只依赖按钮禁用。

## 刷新恢复范围

正式入口注入 sessionStorage，保存键 `class-rollcall.session.v1`，仅保存当前页使用过的记录 ID、创建时间、学号、模式及顺序游标，不保存数据库凭据。

刷新时向服务端核对 ID、calledAt、学号和模式。校验失败或记录不存在时清除该页恢复信息，提示重新点名，不改写服务端历史。查询暂时失败时保留核验入口。没有本页保存记录时，不扫描全库最新未结算记录。

范围是同一浏览器页签的刷新恢复，不是账户或课堂隔离。关闭页签、浏览器禁止/清空存储时不能保证恢复。内存服务重启不持久化记录；ID 复用但创建时间变化时不能误恢复。创建点名请求本身已经提交却丢失响应、而客户端尚未取得记录标识的情况，尚无请求幂等键，仍是后续增强项。
