## 需要主线补齐的入口

遵照对接说明，UI 不直接请求这些已有 HTTP 接口，也没有擅自修改主控。以下为明确的接入提案，尚未实现，需李文龙同步契约后继续联调：

| 操作             | 拟增加回调                                   | 主控行为与展示入口                                                                                                       |
| ---------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 搜索及翻页       | `onStudentsRequested({q, pageNo, pageSize})` | 调 `listStudents`；保存查询状态；使用 `renderStudents(rows,total)` 并补充当前页元数据。首页总人数与筛选命中数分开保存    |
| 查看当前概率     | `onProbabilitiesRequested()`                 | 调 `probabilities`；新增 `renderProbabilities({minScore, rows})`，展示学号、姓名、积分、权重与概率。空名单走统一错误提示 |
| 当前随机记录复演 | `onReplayRequested(recordId)`                | 调 `replayRoll`；新增 `renderReplay(result)`，显示记录号、种子、记录学号、复算学号及 matched；顺序记录不提供该操作       |

搜索时不能用“当前筛选结果为空”判断整个班级不能点名；导出仍取全量最新名单。概率在结算后需重新获取，不能把旧快照标成当前概率。复演证明该结果能按保存数据复算，不单独证明整个系统没有任何人为干预。

当前正式页面仅显示抽签规则说明，没有实时概率表、搜索分页和复演按钮；这些不是已完成事项。大屏和核心 UI 已可独立使用。

还需主线确认：结算请求已提交但响应丢失时的状态查询/恢复；刷新页面后的未结算记录恢复；真实 MySQL 读写和线上部署。当前会话统计只覆盖本次打开页面，不代表全库历史。
