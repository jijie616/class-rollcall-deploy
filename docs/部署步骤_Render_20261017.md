## 第一步：注册 Render，准备 GitHub 部署副本

头歌仍为课程主仓库：https://code.educoder.net/papg79lzu/class-rollcall 。本次移除本机 Git 凭据后，匿名读取实际 Git 地址返回需要密码，因此不能把它当作 Render 可匿名克隆的公共仓库。

推荐通过 Render 支持的 GitHub 连接部署。GitHub 上建立空的部署副本仓库，例如 class-rollcall-deploy，可以设为私有，不生成 README、许可证或 .gitignore。给 Render 的 GitHub 授权只选择这个部署仓库即可。

用户已创建 https://github.com/jijie616/class-rollcall-deploy ，助手核对空仓库后添加单独的 deploy 远程并推送 main；origin 仍指向头歌，没有强制推送，.env 未入库。通过 git push 保留双方提交历史。

不要把含用户名、密码或 Token 的 URL 填入聊天、render.yaml 或仓库配置文件。

## 第二步：创建 Web Service

在 Render 控制台选择 New → Web Service，通过 Git Provider 连接 GitHub 部署副本。原生 Node 环境建议填写：

| 字段               | 值                                                    |
| ------------------ | ----------------------------------------------------- |
| Name               | class-rollcall，冲突时添加学号后缀                    |
| Branch             | main                                                  |
| Root Directory     | 留空，package.json 位于仓库根目录                     |
| Language / Runtime | Node                                                  |
| Region             | 若该区域有 Free，优先 Singapore；实际出网连接仍需验收 |
| Build Command      | npm ci --omit=dev                                     |
| Start Command      | npm run start:mysql                                   |
| Instance Type      | Free，创建前确认价格为 $0                             |
| Health Check Path  | /healthz                                              |

服务监听平台注入的 PORT，地址为 0.0.0.0；不用创建新 MySQL 或 Render Postgres，不执行自动建表或测试数据写入。

repo 内的 render.yaml 记录相同字段，供支持 Blueprint 的 GitHub 连接流程参考；本轮没有在云端提交 Blueprint。手工 Web Service 表单也可以按本表配置。官方说明：[Web Service](https://render.com/docs/web-services)、[Blueprint 字段](https://render.com/docs/blueprint-spec)。

## 第三步：填写平台环境变量

| 环境变量            | 填写内容                                                             |
| ------------------- | -------------------------------------------------------------------- |
| NODE_ENV            | production                                                           |
| NODE_VERSION        | 24，限定当前本地已验证的大版本                                       |
| STORE               | mysql                                                                |
| DB_HOST             | 本机 .env 中的主机地址，主机不带端口                                 |
| DB_PORT             | 本机 .env 中的实际端口                                               |
| DB_NAME             | 本机 .env 中的数据库名                                               |
| DB_USER             | 本机 .env 中的数据库账号                                             |
| DB_PASSWORD         | 本机 .env 中的数据库密码，仅填入平台的私密变量                       |
| APP_ACCESS_USER     | 自定课堂网站访问账号，如 teacher                                     |
| APP_ACCESS_PASSWORD | 新设置至少 12 字符的独立访问口令，建议 16 字符以上，不使用数据库密码 |

PORT 由平台注入，不把本机的 8787 固定到云端；不要上传 .env 文件。

访问账号是网站登录用的共享账号，与数据库账号分开。生产环境缺少完整访问配置或口令过短，应用会拒绝启动；正常访问时浏览器弹出账号密码框。健康检查 /healthz 不要求账号，仅返回 {ok:true} 或 {ok:false}，不返回名单、密码或数据库错误详情。

这是课程演示用的共享访问门禁，不是个人账户、角色权限或不同课堂之间的数据隔离。公网使用必须是平台 HTTPS 地址；需要交给老师的访问账号口令单独提供，不写入公开博客或源码。

## 第四步：部署后验收

1. 构建日志安装成功，启动日志显示 MySQL 模式，无缺失配置错误。
2. 公网 /healthz 返回 200 且 {ok:true}；503 表示实际数据库链路尚不可用，需要查平台网络和配置，不能仅看“进程已启动”。
3. 未登录访问首页或 /api/students 得到登录要求，不能匿名写入 /api/roll。
4. 登录后正式页面和静态资源可用，先只读核对现有名单，不对真实班级数据运行 smoke-e2e。
5. 需要写入验收时，先明确专用虚拟学号和清理范围，验证点名、结算、恢复、概率、复演、排行与全量导出。
6. 服务重启后数据仍保留；用第二台设备或手机访问，区分真实手机和模拟窄屏记录。
7. 确认老师的设备可访问公网地址及登录，再制作视频和整理博客。

健康检查遵照 [Render HTTP 健康检查](https://render.com/docs/health-checks)；当前会执行只读名单查询以确认数据库连接可用。公网接口可达，但托管环境到数据库的连接尚未通过，真实手机验收未执行，不以本地通过代替。
