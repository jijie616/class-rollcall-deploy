## 这是什么

老师上课用的随机点名工具。导入班级名单后可以随机点名或按学号顺序点名，点到谁就登记课堂表现并结算积分，最后按积分排名、导出详单。

关键设计有两条：

1. **抽签是加权的**——总积分越高的同学，被随机点到的概率越低（题目 Part·1 1.1 第 5 条的硬性要求）。
2. **抽签结果可复演**——每次抽签把随机种子和当时的名单快照一起落库，任何人可以按记录 id 让服务端原样复算一次。因为题目把「抽取非随机」明确列为判 0 项，这条是主动自证清白。

## 开发过程中发现并修掉的两个真实缺陷

留在这里是为了博客 3.6 与 4.3 能写具体的东西，而不是空泛的"遇到了一些困难"。

**1. `Number(null) === 0` 把"字段漏传"变成了"未到场"**（`scorer.js`）
最初用 `Number(input.present)` 解析到场状态。前端一旦漏传 `present`，它会被静默当成 0（未到场），**把该学生本次的得分直接清零**——不报错、不提醒，属于静默数据损坏。同一个陷阱还让 `''`、`false`、`[]` 都能冒充合法的"回答加 0 分"。
改法：`parsePresent` 只接受 `1/0/true/false`，其余一律抛错；`isValidAnswerBonus` 与 `currentScore` 同样先校验类型再校验范围。

**2. HTTP 请求体被整个丢弃，而单元测试完全察觉不到**（`api.js` + `index.js`）
原先处理函数签名不统一（有的收 `(params)`，有的收 `(params, body)`）。HTTP 层调用时把路由参数当成第一个实参，**请求体被丢掉**——于是 `roll({mode})`、`rollNext({cursor})`、`validateImport({rows})` 通过 HTTP 调用时全都收不到入参。单元测试直接调函数、把 body 当第一个参数传，所以 41 项接口测试全绿却掩盖了这个问题；**只有真实启动服务、跑端到端冒烟才暴露出来**（表现为：无论传什么游标都返回第一位同学）。
改法：所有处理函数统一只接收一个对象，由 HTTP 层合并「路径参数 + 查询串 + 请求体」后传入；并补了 4 项"接线回归"测试，专门盯这类问题。

> 这两条合起来说明一件事：**只测函数不测真实服务，会漏掉一整类接线错误**。

## 关键算法

**中签权重**

```
w = 1 / (1 + score - minScore)
```

`minScore` 是本次抽签快照里的最低积分，先平移再取倒数。这样：分母恒 ≥ 1（不会除零）、权重恒为正、同一份名单内积分越高权重严格越低。

> 为什么不用更直观的 `w = 1 / (1 + score)`：题目允许扣分，积分为 −1 时直接除零，分数更低时权重会变成负数。这个问题在原型阶段发现，`tests/test-lottery.js` 里有对应的回归用例。

**抽样方法**：轮盘赌（roulette wheel），O(n)。种子来自 `crypto` 真随机源，抽签本身用确定性 PRNG（mulberry32），因此「随机但可复现」。

**积分规则**：初始 0；点到且到场 +1；准确复述问题 +0.5、未准确复述 −1、未提问不评；准确回答 +0.5~3（0.5 步长）；未到场 +0 并跳过后续评分。

分值内部按「半分」整数运算、出口再除以 2，避免 0.5 反复累加产生浮点尾差。

```
SELFTEST|点名=许嘉禾|结算=本次 +4.5， 当前总积分 6.5 （到场 1 / 复述 0.5 / 回答 3）|顺序点名=陈一宁|排行榜行数=8
```
